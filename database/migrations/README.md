# Миграции

`database/init.sql` — baseline версии `2026-09-product-mvp` для новой установки.

Предыдущая учебная схема объединяла тип номера и количество в таблице `rooms`, не содержала e-mail клиентов, ролей, услуг и платежей. Автоматический in-place upgrade не включён, потому что однозначно сопоставить агрегированное количество с физическими комнатами без решения владельца данных невозможно.

Для существующей базы:

1. создать проверенный backup;
2. развернуть новую базу рядом, не поверх старой;
3. импортировать справочники и клиентов с нормализацией e-mail/телефонов;
4. преобразовать каждый старый `rooms.quantity` в отдельные физические комнаты;
5. перенести брони и сверить суммы/даты;
6. переключить приложение только после acceptance-проверки.

Новые изменения схемы добавляются отдельными идемпотентными SQL-файлами и регистрируются в `schema_migrations`.
