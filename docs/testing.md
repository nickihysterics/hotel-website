# Тестирование и приёмка

## Автоматические проверки

### Конфигурация

```bash
docker compose config --quiet
docker compose run --rm --no-deps web composer validate --strict
```

### Код

```bash
docker compose run --rm --no-deps web composer check
```

Команда включает:

1. `php -l` для PHP-файлов приложения;
2. PHPStan уровня 6;
3. PHP-CS-Fixer в режиме проверки.

### HTTP smoke

```bash
docker compose up -d --build
BASE_URL=https://localhost ./scripts/smoke.sh
```

Smoke проверяет публичные страницы, формы входа, защищённый dashboard сотрудника,
основные рабочие разделы и личный кабинет гостя.

## Ручной приёмочный чек-лист

### Публичная часть

- главная загружается без ошибок;
- каталог отражает записи MySQL;
- фильтры дат, гостей, категории и цены применяются;
- недоступный тип не предлагается к бронированию;
- мобильная навигация и формы остаются рабочими.

### Регистрация и вход

- новый уникальный гость регистрируется;
- повторный email или телефон отклоняется;
- неверный пароль не создаёт сессию;
- гость не открывает `/admin/`;
- сотрудник не попадает в гостевой кабинет;
- выход завершает текущую авторизацию.

### Бронирование

- обратные и прошлые даты отклоняются;
- вместимость проверяется;
- пересекающаяся бронь сверх фонда не создаётся;
- цены услуг соответствуют способу тарификации;
- сумма в базе совпадает с детализацией;
- созданная бронь видна только её владельцу.

### Оплата и услуги

- успешный sandbox-платёж создаёт `paid`;
- отклонённый платёж создаёт `failed`;
- повторно оплачивается только остаток;
- дозаказанная услуга меняет итог;
- отменённая услуга исключается из суммы;
- отмена гостя переводит demo-платёж в `refunded`.

### Операционный день

- `pending` подтверждается;
- заселение предлагает только свободные комнаты нужного типа;
- после check-in комната становится `occupied`;
- после check-out комната становится `dirty` и создаётся уборка;
- завершение уборки возвращает `available`;
- недопустимый переход статуса отклоняется.

### Роли

- `reception` не управляет пользователями и системным каталогом;
- `housekeeping` не видит финансовые и клиентские разделы;
- `analyst` не изменяет операции;
- `manager` работает со всеми прикладными разделами;
- `admin` имеет полный доступ.

### Отчётность

- KPI не делят на ноль при пустом фонде;
- ADR и RevPAR соответствуют тестовому набору;
- каждый из шести экспортов открывается в Excel/LibreOffice;
- шапка XLSX закреплена, фильтр присутствует, числа остаются числами.

## Проверка базы

Для чистой приёмки используйте отдельный демонстрационный volume:

```bash
docker compose down -v
docker compose up -d --build
BASE_URL=https://localhost ./scripts/smoke.sh
```

Команда `down -v` необратимо удаляет локальные данные и не применяется к среде,
где есть ценная информация.

## Критерии готовности

Версия готова к публикации, когда:

- рабочее дерево чистое;
- Composer validation, lint, PHPStan и style проходят;
- Compose-конфигурация валидна;
- smoke проходит на чистой базе;
- документация соответствует интерфейсу и схеме;
- GitHub Actions завершён успешно.
