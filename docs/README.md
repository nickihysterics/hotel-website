# Документация Hotel Website

Этот каталог — единый комплект проектной, пользовательской и эксплуатационной
документации. Тексты описывают состояние ветки `main`; при изменении поведения
приложения связанный документ обновляется в том же коммите.

## Как читать

### Для защиты курсовой

1. Начать с корневого `README.md`.
2. Сверить согласованные требования в [product.md](product.md).
3. Объяснить архитектуру и ER-модель по [architecture.md](architecture.md).
4. Провести показ по [demo.md](demo.md).
5. Подтвердить качество командами из [testing.md](testing.md).

### Для локального запуска

1. Выполнить раздел «Быстрый запуск» из корневого README.
2. При проблемах свериться с [deployment.md](deployment.md).
3. Использовать только демонстрационные учётные записи.
4. Перед изменением кода изучить [development.md](development.md).

### Для пилотного внедрения

1. Проверить границы MVP в [product.md](product.md).
2. Закрыть production-пункты из [security.md](security.md).
3. Подготовить инфраструктуру по [deployment.md](deployment.md).
4. Выполнить полный приёмочный чек-лист из [testing.md](testing.md).

## Источники истины

- схема новой установки и demo-seed — `database/init.sql`;
- матрица ролей — `src/Security/Auth.php`;
- доменные расчёты — `src/Service/`;
- конфигурация контейнеров — `compose.yaml` и `deploy/`;
- набор автоматических проверок — `composer.json` и `.github/workflows/ci.yml`.

Если документация расходится с кодом, это считается дефектом. Исправление должно
синхронизировать реализацию, README и профильный документ.
